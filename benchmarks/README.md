# Benchmarks — INLA.jl vs R-INLA

Performance harness for the three flagship oracle datasets:

- **Scotland BYM2** (areal Poisson, 56 districts, 4 disconnected components),
- **Pennsylvania BYM2** (areal Poisson, 67 counties, single connected graph),
- **Meuse SPDE** (geostatistics, ~2,000-vertex SPDE mesh, Gaussian observation
  model).

Quality (posterior agreement) is gated by per-package `test/oracle/` suites.
This directory is performance-only: wall-clock + memory under
single-threaded BLAS on both sides, regenerated by a single command and
versioned in-repo so the gap is visible release over release.

## Layout

```
benchmarks/
├── Project.toml      # BenchmarkTools, RCall, JLD2 + the in-tree packages
├── run.jl            # entry point: orchestrates Julia + R, writes the report
├── harness.jl        # Julia-side timing via BenchmarkTools.@benchmark
├── r_inla.R          # R-INLA fits for the same three datasets
├── compare.jl        # markdown formatter for the joint results table
└── results/          # one file per (date, arch) — versioned alongside the harness
    └── YYYY-MM-DD_<arch>.md
```

## Running

From the repository root:

```
julia --project=benchmarks -e 'using Pkg; Pkg.instantiate()'
julia --project=benchmarks benchmarks/run.jl
```

The first run resolves `[sources]`-pinned in-tree packages and pre-builds
RCall; subsequent runs are pure timing. Each result file carries the full
environment block (R-INLA version, Julia + ecosystem versions, hardware
spec, BLAS thread count) — read the file's header for the run-specific
context.

## Methodology

- **Same input.** Both engines fit the same dataset shape (Scotland: 56
  districts + AFF covariate + BYM2 with PC priors; PA: 67 counties +
  smoking covariate + BYM2; Meuse: log-zinc + dist-to-river + SPDE-Matérn
  α=2). The R harness rebuilds the inputs from `SpatialEpi`/`sp` raw
  datasets; the Julia harness reads the JLD2 oracle fixtures shipped with
  the test suite.
- **Warm-up discarded.** First fit on each side is discarded as JIT /
  binary-load priming; subsequent runs feed the median + IQR.
- **Single-threaded BLAS.** Both sides forced to one BLAS thread to
  remove parallelism noise from the comparison. Multi-threaded numbers
  are a separate table planned for future result files once the
  `GMRFsPardiso.jl` factorisation backend lands.
- **Pinned versions.** R-INLA version pulled from `packageVersion("INLA")`
  at run time; Julia ecosystem versions from `Pkg.dependencies()`. Both
  land in the result file's header.
- **Hardware in the filename.** `results/<date>_<arch>.md` is the canonical
  reference per release.

## Requirements

- R + R-INLA on `$PATH` (so `using RCall; R"library(INLA)"` resolves).
  Tested with R 4.5+ and R-INLA 25.10+.
- The R packages `SpatialEpi`, `spdep`, `sp` for the dataset inputs.
- Julia 1.12+ (the rest of this ecosystem's compat baseline).

## Out of scope

- **NIMBLE / Stan triangulation.** Tier-3 cross-checks live in
  `packages/LGMTuring.jl/test/triangulation/` against AdvancedHMC; NIMBLE
  is not on the roadmap.
- **Auto-published charts.** Single result files per release are
  enough; no time-series plotting harness here.
- **CI gating.** The harness is for human-driven runs on a known
  machine. CI hardware is too noisy to publish numbers from.
